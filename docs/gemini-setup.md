# Adporter 성과 요약 코멘트

## 현재 동작

- 요약 페이지 상단에서 최신 업로드 날짜를 기준으로 전일·전주 동요일을 비교한다. 광고비·구매·매출·CPA·ROAS 기본 코멘트는 외부 API 없이 계산한다.
- Gemini는 집계 지표를 받아 핵심 판단·비교 근거·점검 제안을 작성한다. 원본 CSV·실제 캠페인명·소재명은 보내지 않는다. 합계 비율은 합계끼리 나눈다.
- 분석 입력이 바뀌면 자동 요청한다. 동일 계정·분석 입력·메모·업종 설정·모델·지침의 **완성된 결과**는 서버에서 재사용한다. 새로고침·같은 CSV 재업로드·대기 시간 변경은 추가 생성을 요구하지 않는다. 같은 입력이면 다음 날도 재사용한다.
- 운영 메모와 업종 설정은 '설정 저장 후 분석'으로 적용한다. 입력 중에는 생성하지 않는다. 업종·상품·수요 시기·대표 지역·대기 시간은 계정별 브라우저 localStorage, 메모는 계정·기준일·매체별 localStorage에 저장한다. 다른 기기에는 동기화하지 않는다.
- 상태 안내·대기 시간 막대를 표시한다. 막대는 AI 작업 진행률이 아닌 시간 경과다. 대기 시간 선택은 10/20/30/45/60/120/150초, 새 기본값은 150초다. 기존 저장 선택은 유지한다.
- Gemini 스트리밍 응답을 서버에서 수집한다. 전체 답변이 끝나면 완성 분석, 제한 시간이나 토큰 한도에 도달해도 완성 문장이 있으면 부분 분석을 제공한다. 문장 중간의 꼬리와 내부 추론은 제외한다. 부분 결과는 저장하지 않으므로 재시도는 새 호출이다.
- AI 본문이 전혀 오지 않거나 완성 문장이 없으면 그 사실과 기본 수치 비교를 표시한다. 503·네트워크 오류도 자동 반복 호출하지 않는다.

## 비용 보호와 사용 한도

- Google 검색·시즌·뉴스 자동 조사는 **비활성화** 상태다. 검색 모듈은 제거했다. research_context DB 열은 기존 배포 호환을 위해 남겨 두며 비활성 상태만 저장한다.
- `ADPORTER_AI_ENABLED=true`가 아니면 서버는 외부 요청 전에 중단한다. 브라우저는 비용 보호·부분 분석을 지원하는 최신 서버인지 GET으로 확인한 뒤 생성 요청을 보낸다.
- Gemini 작성 요청은 1회만 실행한다. 유료 모델 전환·유료 검색·자동 재시도·결제 활성화는 하지 않는다.
- 사용자당 한국 시간 하루 10회, Adporter 전체 하루 20회, 계정별 최소 간격 1분이다. PostgreSQL의 트랜잭션 잠금으로 동시 예약도 직렬화한다. 실패·시간 초과도 예약 횟수에 포함한다. 캐시 적중은 0회다.
- Google 프로젝트의 Free Tier 및 사용하는 모델의 무료 지원 여부를 확인한 뒤 AI를 활성화한다. 코드의 활성화 스위치는 Google 결제 등급을 실시간 검증하지 않는다. 나중에 프로젝트를 Paid Tier로 바꾸면 과금될 수 있으므로 호출 한도를 금액 상한이라고 안내하지 않는다.
- 무료 입력은 Google 제품 개선에 사용될 수 있으므로 데모는 가상 CSV로 확인한다. 실제 고객 데이터 전송은 별도 검토한다.
- Supabase 무료 실행 한도에 여유를 두어 서버는 최대 약 140초, 화면은 최대 150초로 제한한다. 세션·준비 확인 시간을 제외한 남은 예산을 서버에 전달하고 부분 응답 반환 시간을 확보한다. 연결 취소는 이미 시작된 공급자 작업의 취소나 사용량 환급을 보장하지 않는다.
- 서류도우미와 같은 Google 프로젝트라면 공급자 무료 할당량·결제 등급은 공유할 수 있다. Adporter의 DB 한도는 다른 서비스에는 적용되지 않는다.

## 서버 설정과 배포

1. Adporter의 Supabase 프로젝트 SQL Editor에서 `supabase/migrations/202610190001_ai_comment_limits.sql`을 실행한다. 기존 광고 테이블을 변경하지 않고 AI 한도 테이블·예약 RPC를 만든다. 재실행 시 기존 기록을 유지한다.
2. Edge Functions → Secrets에 아래 값을 저장한다. 기존 서류도우미의 GEMINI_API_KEY·GEMINI_MODEL 등은 변경하지 않는다.

| 이름                         | 값                                                                         |
| ---------------------------- | -------------------------------------------------------------------------- |
| ADPORTER_GEMINI_API_KEY      | Adporter용 Gemini 키                                                       |
| ADPORTER_GEMINI_MODEL        | 사용 가능한 무료 지원 텍스트 모델 ID. 현재 시연은 gemini-3.8-flash         |
| ADPORTER_AI_ALLOWED_USER_IDS | Authentication → Users에서 확인한 Adporter 로그인 UID. 여러 명은 쉼표 구분 |
| ADPORTER_AI_ENABLED          | 무료 사용 조건 확인 후 true. 미설정·다른 값은 중지                         |

3. 기본 제공 SUPABASE_URL·SUPABASE_ANON_KEY·SUPABASE_SERVICE_ROLE_KEY를 사용한다. service_role은 한도 RPC와 결과 저장에만 쓰며 브라우저에는 절대 전달하지 않는다.
4. `report-comment`라는 함수 안에 아래 세 파일을 **같은 위치**에 넣어 배포한다. 기존 파일 아래에 덧붙이지 말고 내용 전체를 교체한다.

```text
index.ts
handler.js
weather.js
```

5. Verify JWT는 OFF로 두되 함수 내부에서 Auth 서버로 로그인 토큰을 검증하고 허용 UID를 확인한다. 익명 요청이나 비허용 계정은 실행하지 못한다. 다른 함수 설정은 바꾸지 않는다.
6. Deploy updates 성공 후 로컬 앱을 새로고침한다. SQL·Secret·서버 함수 배포와 GitHub Pages 프론트엔드 배포는 별개다. 로컬 수정만으로 이미 배포된 함수가 바뀌지 않는다.

CLI를 이미 사용하는 환경에서는 `supabase functions deploy report-comment --no-verify-jwt`로 배포할 수 있다. 프로젝트 연결과 로그인은 별도로 준비해야 한다.

## 날씨와 업종 배경

- 업종·상품·주요 수요 시기를 자유 입력한다. 수요 시기는 사용자 제공 가설이며 외부 사실로 확인된 것이 아니다. 시즌·이슈 자동 검색은 하지 않는다.
- 날씨 참고는 기본 OFF다. 켜면 지원하는 대표 도시 하나를 선택한다. 전국 평균이나 사용자 현재 위치를 추정하지 않는다.
- 서버가 Open-Meteo에서 세 비교 날짜의 평균기온·일강수량을 조회한다. 최근 자료는 Forecast API의 과거 구간, 오래된 날짜는 Historical Weather API를 사용한다. 모델 기반 추정치이며 관측소 실측값과 다를 수 있다.
- 한국 시간 오늘·미래 날짜는 완료된 날씨 근거로 사용하지 않는다. 기준일 대비 평균기온 3℃ 이상 또는 강수량 5mm 이상 차이가 나는 비교만 설명 후보로 제공한다. 이는 통계적 유의성 기준이 아니다.
- 상품과의 관련성이 약하면 Gemini가 설명을 생략하도록 지시한다. 기온 변화가 성과의 원인이라고 확정하지 않는다. 날짜별 값과 Open-Meteo/CC BY 4.0 출처를 화면에서 확인할 수 있다. 조회 실패에도 성과 분석은 계속한다.
- 무료 Open-Meteo는 비상업용 포트폴리오 데모에만 사용한다. 상업용 운영은 제공자 조건에 맞는 구독 또는 다른 제공자가 필요하다. 별도 상업용 키가 있다면 ADPORTER_WEATHER_API_KEY로 customer API를 사용할 수 있으나 자동 구매하지 않는다.
- 날씨 API에는 좌표·날짜만 보낸다. Gemini에는 익명 성과 집계·적용한 메모·업종 설정·선택한 날씨를 전달한다. 메모에 고객명이나 개인정보를 넣지 않는다.

## 표현 교정과 매체 기여

- 맞춤법·띄어쓰기·조사·문장 호응을 생성 마지막에 점검하도록 지시한다. 전환당 비용·구매 전환율·전주 동요일 대비 표기는 코드로 통일한다. 모든 자유 문장의 정확성을 보장하는 맞춤법 엔진은 아니다.
- 유의미하게·통계적으로 유의한·폭발적·압도적·획기적 등 과장 표현을 정리한다.
- AI가 쓴 매체의 주도·견인·기여·뒷받침 주장을 제거한다. 전체 매체 집계와 합계가 일치하고 비교 날짜가 모두 있을 때만 수치 기여 문장을 코드로 덧붙인다.
- 전체 매출이 증가하고, 증가한 매체들의 증가액 중 단독 1위 비중이 50% 이상인 경우에 증가액과 비중을 표시한다. 다른 매체 감소로 분모가 줄어 과장되지 않도록 양의 증가액 합계를 사용한다. 이 기준은 인과관계나 통계 검정이 아니다.
- 상위 캠페인 일부로 전체 매출 기여를 추정하지 않는다. AI가 쓴 나머지 숫자·해석은 광고주 보고 전 사용자가 확인한다.

## 검증과 오류 확인

```powershell
npm test
npm run lint
npm run build
```

- 가상 CSV의 새 분석 → 생성 시각 확인 → 새로고침 → 저장된 분석 재사용 확인.
- 같은 CSV 재업로드, 매체 전환, 설정 저장, 메모 적용, 부분 분석·시간 초과 안내를 점검한다.
- 401은 로그인/Verify JWT, 403은 허용 UID, 503은 응답 문구에서 설정 미완료와 Gemini 일시 불가를 구분한다. 연속 실패로 한도를 소비하지 않도록 반복 클릭하지 않는다.
- 한도가 차면 한국 시간 자정까지 기다린다. 운영에서 기록 삭제로 초기화하면 사용 기록과 저장 코멘트도 사라지므로 임의로 초기화하지 않는다.
- 자동 테스트는 모의 네트워크를 사용한다. 실제 Supabase SQL·정책·로그인·공급자 가용성은 라이브 환경에서 별도로 확인한다.
