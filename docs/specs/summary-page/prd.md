## 1. 개요

- **목표:** 마케터가 아침에 열어서 최근 광고가 돈을 벌었는지 **10초 안에** 판단한다.
- **대상:** 네이버·메타·구글 광고를 함께 돌리는 퍼포먼스 마케터. 그리고 이 포트폴리오를 보는 사람(면접관 등).
- **배경:** test1007 요약 페이지를 더 탄탄한 기초(spec·디자인 규칙·검문소)로 다시 만든다. 백엔드(`/api/reports`, Spring Boot + MySQL)는 test1007 것을 **그대로** 쓴다.
- **화면 구성 (위→아래):** 머리글([양식 내려받기] [CSV 업로드], [요약] [원본 데이터] 이동) → 매체 필터 → 기준일·업로드 지연 경고 → 합계 카드 4개(최근 7일 + 전주 대비) → 퍼널 분석(단계 흐름 + 매체별 비교·최저) → 최근 14일 CPA·ROAS 그래프 → 최근 3개월 월 누적 그래프 + 전월 대비 → 월 누적 표 → 일자별 표
- **성공 기준:**
  - 휴대폰(360~390px) 첫 화면에 합계 카드 4개와 전주 대비가 모두 보인다.
  - 전주 대비를 색과 "개선/악화" 글자만으로 읽을 수 있다 (머릿속 계산 없음).
  - 서버가 잠든 상태로 처음 열어도 안내 문구가 바로 보인다.
  - 화면 어디에도 `NaN`·`Infinity` 가 나오지 않는다.
  - 내려받은 98일 파일을 엑셀로 열면 한글이 깨지지 않고, 그 파일을 그대로 다시 업로드할 수 있다.

## 3. 기술 결정 (ADR)

> 각 결정은 **맥락 → 대안 → 결정 → 결과** 순서로 적는다. 결정이 바뀌면 코드 구조가 바뀌므로 가장 신중하게 정한다.

### ADR-1. 페이지 이동·주소 관리 → **React Router + Vercel**

- **맥락:** 지금은 `/` 하나지만 다음 기능으로 `/campaigns` 가 생긴다. 매체 필터를 주소(`?media=`)에 남겨야 한다 (spec 결정 6).
- **대안:** React Router / 직접 만들기(브라우저 history 기능).
- **결정:** React Router. 화면은 **Vercel** 에 배포한다.
  - 새로고침·링크로 바로 들어올 때 404 가 나지 않도록 `vercel.json` 에서 모든 주소를 `index.html` 로 보낸다.
  - 매체 값은 대소문자를 가리지 않는다 (`meta` → `META`). 없는 값(`KAKAO`)이면 "전체"를 보여준다. **주소창은 고치지 않는다.**
- **결과:**
  - 장점: 페이지가 늘어도 구조가 그대로이고, 주소 읽기/쓰기(`useSearchParams`)를 같은 도구로 한다. 주소가 `/campaigns` 처럼 깔끔하다.
  - 단점: 패키지 1개 추가. `?media=KAKAO` 일 때 주소와 화면(전체)이 다를 수 있다.
  - 달라지는 것: `main.jsx` 에서 앱을 라우터로 감싼다. 저장소에 `vercel.json` 이 생긴다.

### ADR-2. 데이터를 언제, 얼마나 받을지 → **처음에 전체를 한 번**

- **맥락:** `GET /api/reports` 는 기간·매체로 골라 받는 기능이 없고, 백엔드는 고치지 않는다. 예상 데이터는 1,000줄 이상, 수천 줄 규모.
- **대안:** 처음에 전체를 받아 화면에서 나눠 계산 / 필요할 때마다 골라 받기(백엔드 수정 필요 → 불가).
- **결정:** `App.jsx` 가 처음 열릴 때 전체를 한 번 받는다. 매체를 바꿀 때는 다시 받지 않는다. CSV 업로드에 성공하면 한 번 다시 받는다.
- **결과:**
  - 장점: 백엔드 그대로. 필터 전환이 즉시. 98일 내려받기도 서버 호출 없이 화면에서 파일을 만든다.
  - 단점: 데이터가 많아질수록 첫 화면이 느려진다 (수천 줄은 약 1MB 이하라 문제없음).
  - 나중에 할 일: 1만 줄을 넘어 느려지면 백엔드에 기간 골라 받기를 추가한다.

### ADR-3. 필터 상태를 어디에 둘지 → **주소(URL)**

- **맥락:** spec 결정 6 에서 "매체는 주소에 남긴다" 로 정했다.
- **대안:** 주소 / `useState` 만 (새로고침하면 사라져 spec 위반) / 브라우저 저장소 (링크 공유 불가).
- **결정:** `?media=` 에 둔다. 읽기·틀린 값 처리는 ADR-1 규칙을 따른다. 기간 필터는 없다.
- **결과:**
  - 장점: 새로고침해도 유지되고 링크로 같은 화면을 공유한다.
  - 단점: 주소 값은 사람이 고칠 수 있어서 항상 검사해야 한다.
  - 달라지는 것: 필터 값은 `useState` 가 아니라 주소에서 읽는다 (CLAUDE.md "상태 관리: useState 만" 의 예외).

### ADR-4. 그래프 라이브러리 → **Recharts**

- **맥락:** 필요한 건 선 그래프(최근 14일, 최근 3개월)와 막대 그래프(WoW · MoM 비교, 2026-10-13 추가). 휴대폰 너비에 맞게 줄어들어야 한다.
- **대안:** Recharts / Chart.js (React 연결 패키지 추가 필요) / 직접 SVG (축·툴팁을 모두 직접 만들어야 함).
- **결정:** Recharts. **흐름은 선, 비교는 막대.**
  - 선: 날짜 · 월처럼 이어지는 흐름 (최근 14일, 최근 3개월 월 누적).
  - 막대: 두 기간을 나란히 키 재기 (WoW 이번 주 vs 지난주, MoM 같은 기간). 막대는 0 에서 시작한다.
  - 값이 `-` 인 날(분모 0)은 **선을 끊는다**. 0 으로 그리지 않는다 (CPA 0원 = 좋은 날로 잘못 읽힘). 툴팁에 "구매 0건이라 계산 불가" 를 보여준다.
  - 휴대폰에서 세로축 숫자는 줄여 쓴다 (`1.2만`). 툴팁에는 원래 숫자(`12,000원`)를 보여준다.
- **결과:**
  - 장점: React 부품처럼 쓰고, 화면 너비 맞춤 기능이 있다. test1007 과 같아 참고하기 쉽다.
  - 단점: 용량이 비교적 크다.
  - 달라지는 것: 그래프 데이터에서 계산 불가 값은 `null` 로 넘긴다.

### ADR-5. CSV 읽기 → **Papa Parse + 화면에서 먼저 검사**

- **맥락:** 엑셀에서 저장한 CSV 를 화면에서 읽어 `POST /bulk` 로 보낸다. 서버는 한 줄이라도 틀리면 전부 거부하는데, 몇 번째 줄이 틀렸는지 알려주는지는 정해져 있지 않다. 한국 엑셀 기본 CSV 는 EUC-KR 이고, 날짜·숫자 모양을 바꿔 저장한다.
- **대안:** Papa Parse / 직접 `split(',')` (칸 안 쉼표에서 칸이 밀림). 검사는 화면이 먼저 / 서버에만 맡김.
- **결정:** Papa Parse 로 읽고, 보내기 전에 화면이 줄마다 검사한다.
  - 한글: UTF-8 로 읽어 보고 깨지면 EUC-KR 로 다시 읽는다 (브라우저 기본 기능, 추가 설치 없음).
  - 제목 줄: 양식과 같은 한글 이름으로 칸을 찾는다. 순서는 달라도 되고, 필요한 칸이 빠지면 업로드를 멈추고 알려준다.
  - 자동 정리: 날짜 `2026/10/1`, `2026. 10. 1.` → `2026-10-01`. 숫자 `100,000` → `100000`. 그 밖의 모양은 틀린 줄.
  - 검사 규칙은 api.md 와 같다 (필수값, 0 이상 정수, 매체 3개, 이름 100자 이하). 틀린 줄이 하나라도 있으면 서버로 보내지 않고 "5번째 줄: 광고비는 0 이상의 숫자여야 해요" 처럼 목록으로 보여준다.
- **결과:**
  - 장점: 마케터가 엑셀 저장 방식을 신경 쓰지 않아도 되고, 틀린 줄을 줄 번호로 바로 안다 (사용자 이야기 7).
  - 단점: 패키지 1개 추가. 검사 규칙이 서버와 화면 두 곳에 있어서, 서버 규칙이 바뀌면 화면도 고쳐야 한다.
  - 달라지는 것: 읽기·정리·검사 함수는 `src/utils/` 의 순수 함수로 두고 `node --test` 로 테스트한다.

### ADR-6. 날짜 계산 → **date-fns + "오늘"은 한국 시간**

- **맥락:** 기준일 −6일, 전주, 최근 14일·98일, 3개월, 업로드 지연 일수를 계산한다. JS 기본 `new Date('2026-10-01')` 은 UTC 로 읽혀 나라에 따라 하루가 밀린다. 업로드 지연의 "어제"는 보는 사람 컴퓨터 시간에 따라 달라진다.
- **대안:** date-fns / 직접 만들기 (월말·윤년·시간대를 모두 직접 테스트) / Day.js (기능마다 플러그인 설정 필요).
- **결정:** date-fns.
  - 기간 계산은 모두 **기준일**로 한다 (오늘로 자르지 않음).
  - "오늘/어제"가 필요한 곳(업로드 지연)은 누가 어디서 보든 **항상 한국 시간(Asia/Seoul)** 으로 정한다 (브라우저 기본 `Intl` 사용).
- **결과:**
  - 장점: `subDays`, `startOfMonth` 처럼 이름으로 뜻이 보이고, 하루 밀림 함정을 막는다. 쓰는 함수만 들어가 가볍다.
  - 단점: 패키지 1개 추가.
  - 달라지는 것: 날짜 함수는 `src/utils/` 한 곳에 모으고, 컴포넌트에서 `new Date()` 를 직접 쓰지 않는다.

### 🆕 원본 데이터 페이지 `/data` · 기간을 골라 내려받기 (spec 결정 7, 2026-10-13)

- 요약 페이지(분석)와 나눈 **데이터 관리** 페이지. 머리글 [요약] [원본 데이터] 로 오가고, 매체 필터(`?media=`)는 같다.
- **기간을 고른다:** 빠른 버튼 [최근 7일] [최근 14일] [최근 98일] [이번 달] + 시작일 · 끝일 직접 고르기. 처음에는 최근 98일(14주, 동요일 비교와 맞춤). 길이 제한 없음.
- 고른 기간 · 매체의 원본 줄을 표로 보여 주고(최신 날짜가 위), 같은 줄을 CSV 로 내려받는다. 서버 호출 없이 이미 받은 데이터로 만든다 (ADR-2).
- 파일: UTF-8 + BOM (엑셀 한글 깨짐 방지), 업로드 양식과 같은 칸(다시 업로드 가능). 이름 `adporter_META_2026-07-02_2026-10-07.csv`.
- 기간 값은 화면 상태(`useState`)로 둔다. 주소에 남기는 것은 매체만.

## 5. 용어 정의

### 데이터 항목 (CSV 제목 줄과 같은 이름)

| 용어                     | 뜻                                                             |
| ------------------------ | -------------------------------------------------------------- |
| 광고비                   | 그날 광고에 쓴 돈 (원)                                         |
| 노출                     | 광고가 화면에 보인 횟수                                        |
| 클릭                     | 광고를 누른 횟수                                               |
| 장바구니                 | 장바구니에 **담은** 횟수                                       |
| 전환                     | **구매 완료** 건수. 화면에서는 "구매" 로 표시                  |
| 매출                     | 광고로 생긴 구매 금액 (원)                                     |
| 매체                     | 광고를 낸 곳: NAVER · META · GOOGLE                            |
| 캠페인 > 광고그룹 > 소재 | 광고 묶음의 큰 단위 > 중간 단위 > 실제 광고 하나 (이미지·영상) |

### 기간

| 용어        | 뜻                                               |
| ----------- | ------------------------------------------------ |
| 기준일      | 데이터에 있는 **가장 마지막 날짜** (오늘이 아님) |
| 최근 7일    | 기준일을 포함한 7일 (기준일 10/7 → 10/1~10/7)    |
| 전주        | 최근 7일 바로 앞의 7일 (9/24~9/30)               |
| 최근 14일   | 기준일을 포함한 14일                             |
| 최근 98일   | 기준일을 포함한 98일 = 14주 (내려받기 범위)      |
| 월 누적     | 기준일이 속한 달과 그 전 2개월, 달마다 합계      |
| 업로드 지연 | 기준일이 어제보다 오래된 상태                    |

### 화면 표현

| 용어        | 뜻                                                                           |
| ----------- | ---------------------------------------------------------------------------- |
| 개선 / 악화 | 지표가 좋은 쪽 / 나쁜 쪽으로 변함 (매출·ROAS 는 ▲ 가 개선, CPA 는 ▼ 가 개선) |
| 변화 (회색) | 좋고 나쁨을 판단하지 않는 지표의 변화 (광고비)                               |
| 퍼널        | 노출 → 클릭 → 장바구니 → 구매 로 고객이 줄어드는 흐름                        |
| 최저        | 매체별 퍼널 비교에서 3개 매체 중 그 단계 비율이 가장 낮은 곳                 |

### 기술

| 용어                    | 뜻                                                                               |
| ----------------------- | -------------------------------------------------------------------------------- |
| API                     | 화면이 서버에 데이터를 달라고 / 저장하라고 요청하는 약속된 주소 (`/api/reports`) |
| CSV                     | 쉼표로 칸을 나눈 표 파일. 엑셀에서 저장할 수 있다                                |
| 디자인 토큰             | `primary`, `muted` 처럼 이름 붙인 색·글꼴 값 (`src/index.css` 의 `@theme`)       |
| ADR                     | 기술 결정 기록. 맥락 → 대안 → 결정 → 결과                                        |
| 배포                    | 화면을 인터넷 주소로 누구나 볼 수 있게 올리는 것 (Vercel)                        |
| 인코딩 (UTF-8 · EUC-KR) | 한글을 파일에 저장하는 방식. 다르게 읽으면 글자가 깨진다                         |
| BOM                     | 파일 맨 앞 표시. 엑셀이 UTF-8 파일임을 알아보게 한다                             |

지표 공식(CTR · CPC · CPB · CPA · ROAS · 담기율 · CVR · 객단가)은 [docs/metrics.md](../../metrics.md) 참고.
