# 요약 페이지 (/) — 확정 주문서

- 처음 주문서: [spec-original.md](spec-original.md)
- 목표: 마케터가 아침에 열어서 **최근 광고가 돈을 벌었는지 10초 안에** 알 수 있어야 한다.
- 참고: test1007 요약 페이지를 다시 만든다. 백엔드(`/api/reports`)는 test1007 것을 그대로 쓴다.
- 지표 공식·합계 규칙·기간 규칙은 [docs/metrics.md](../../metrics.md) 를 따른다. 이 문서는 그 위에 화면 결정만 더한다.

## 화면 구성 (위에서 아래 순서)

1. 머리글: 사이트 이름, **[양식 내려받기] [CSV 업로드]** 버튼, [요약] [원본 데이터] 이동 (내려받기는 원본 데이터 페이지, 2026-10-13)
2. 매체 필터: 전체 / NAVER / META / GOOGLE
3. 기준일 표시 (+ 업로드 지연 경고)
4. 합계 카드 4개: 총 광고비 · 총 매출 · 전체 ROAS · 전체 CPA
5. 퍼널 분석: 단계 흐름 + 매체별 비교 (가장 낮은 단계에 "최저" 표시)
6. 일자별 추이: 최근 14일 CPA · ROAS 선 그래프 (지표 1개당 그래프 1개)
7. 월 누적 추이: 최근 3개월 CPA · ROAS 그래프 + 전월 대비
8. 데이터 표: 월 누적 표 → 일자별 표

## 결정 사항

### 1. 기준일과 업로드 지연

- 모든 기간 계산은 **기준일**(데이터의 마지막 날짜)로 한다. 오늘 날짜로 자르지 않는다.
- 화면 위쪽에 "데이터 기준일 10/7" 을 **항상** 표시한다.
- 기준일이 어제보다 오래됐으면 "⚠ 3일간 업로드 없음" 경고를 추가로 띄운다.
- **왜:** 오래된 숫자를 어제 숫자로 착각하는 것이 10초 판단에서 가장 위험한 실수이고, 계산 기준은 metrics.md 와 같게 유지한다.

### 2. 전주 대비 표시

- 화살표(▲▼)는 **값의 방향**, 색은 **좋고 나쁨**을 뜻한다.

  | 카드      | ▲           | ▼           |
  | --------- | ----------- | ----------- |
  | 총 매출   | 초록 · 개선 | 빨강 · 악화 |
  | 전체 ROAS | 초록 · 개선 | 빨강 · 악화 |
  | 전체 CPA  | 빨강 · 악화 | 초록 · 개선 |
  | 총 광고비 | 회색 · 변화 | 회색 · 변화 |

- 색만 쓰지 않고 **"개선" / "악화" 글자**를 함께 붙인다.
- "악화" 빨강은 대표색(토마토)과 구분되는 색으로 디자인 단계에서 정한다.
- **왜:** CPA 처럼 내려가야 좋은 지표가 섞여 있어 화살표만으로는 머릿속 계산이 한 번 더 필요하고, 한국 사용자는 "빨강 = 상승" 에 익숙해 글자가 있어야 오해가 없다. 광고비는 일부러 늘렸을 수 있어 판단하지 않는다.

### 3. 카드와 퍼널의 기간

- 카드의 **큰 숫자 = 최근 7일**. 작은 글씨 = 전주 값 + 전주 대비.
- 퍼널 분석(단계 흐름 · 매체별 비교)도 **최근 7일**.
- **왜:** 큰 숫자와 ▲▼ 비교가 같은 기간이어야 헷갈리지 않고, 데이터가 1년치 쌓여도 의미가 변하지 않는다. 긴 기간은 아래의 14일 · 3개월 그래프가 맡는다. (test1007 은 큰 숫자가 전체 기간이었다.)

### 4. 데이터가 부족하거나 문제가 있을 때

| 상황                 | 화면                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 데이터 0건           | 카드·그래프를 숨기고 "아직 데이터가 없어요" + **[양식 내려받기] [CSV 업로드]**           |
| 7일 미만 (예: 3일치) | 있는 날로만 계산하고 "최근 3일 기준" 표시. 전주 대비는 `-` + "비교할 지난주 데이터 없음" |
| 불러오는 중          | "서버를 깨우는 중이에요. 최대 1분 걸릴 수 있어요"                                        |
| 서버 오류            | 오류 문구 + **[다시 시도]** 버튼                                                         |

- 전주 데이터가 일부만 있어도(7일 미만) 전주 대비는 `-` 로 둔다.
- **왜:** 무료 백엔드는 15분 쉬면 잠들어 첫 접속이 30초~1분 걸리는데, 안내가 없으면 포트폴리오를 보는 사람이 멈춘 사이트로 오해한다. 빈 화면 대신 다음 할 일을 보여주고, 부족한 데이터로 만든 틀린 비교는 `-` 로 막는다 (분모 0 → `-` 와 같은 생각).

### 5. 모바일 배치 (화면 너비 약 360~390px 기준)

| 부분                   | 모바일                                                              |
| ---------------------- | ------------------------------------------------------------------- |
| 합계 카드 4개          | 2×2 격자                                                            |
| 퍼널 단계              | 세로로 쌓기                                                         |
| 매체 필터              | 한 줄 유지 (버튼 작게)                                              |
| 그래프                 | 위아래로 쌓기                                                       |
| 데이터 표              | **표 상자 안에서만** 가로 스크롤 (페이지 전체는 가로로 밀리지 않음) |
| CSV 업로드 · 양식 버튼 | 머리글에 유지                                                       |

- **왜:** 카드 4개가 첫 화면에 한 번에 보여야 10초 판단이 되고, 페이지 전체가 옆으로 밀리면 불편하다. 휴대폰으로 포트폴리오를 보는 사람도 그래프·표를 볼 수 있어야 한다. (test1007 은 모바일 대응을 되돌렸다.)

### 6. 필터

- 요약 페이지에는 **기간 필터를 두지 않는다.**
- 매체 필터 값은 **주소에 남긴다**: `/?media=META`. 새로고침해도 유지되고, 주소를 공유하면 같은 화면이 열린다. 값이 없거나 틀리면 "전체".
- 매체 필터는 카드 · 퍼널 단계 흐름 · 그래프 · 표에 적용한다. **매체별 퍼널 비교는 필터와 무관하게 3개 매체를 모두** 보여준다 (metrics.md).
- **왜:** 기간은 규칙으로 정해져 있어(카드·퍼널 7일, 그래프 14일, 월 누적 3개월) 기간 필터를 더하면 적용 범위가 헷갈린다. 자유로운 기간 조회는 캠페인 페이지가 맡는다. 매체를 주소에 남기면 "META 봐 주세요" 를 링크 하나로 공유할 수 있다.

### 7. 원본 데이터 내려받기 (2026-10-13 변경: 90일 고정 → 기간 선택, 원본 데이터 페이지로)

- **원본 데이터 페이지(`/data`)**에서 기간을 골라 그 기간의 데이터를 CSV 파일로 내려받는다. 빠른 버튼 최근 7일 · 14일 · 98일 · 이번 달 + 직접 고르기, 처음에는 **최근 98일**(14주).
- **매체 필터를 적용한다.** 버튼 글자에 범위를 쓴다: `META · 7/2~10/7 내려받기`.
- 파일에는 **원본 줄 그대로** 담는다 (업로드 양식과 같은 칸). 지표 칸은 넣지 않는다.
- 고른 기간에 데이터가 적으면 있는 날만 담는다. 0건이면 버튼을 숨긴다.
- **왜:** 마케터가 최근 3개월쯤을 엑셀에서 직접 가공하거나 보고서에 붙일 수 있어야 한다. 원본 그대로면 내려받은 파일을 다시 업로드할 수 있고, "지표는 화면에서 계산한다" 는 규칙과도 맞는다. 보이는 매체 = 받는 파일이 직관적이고, 버튼에 범위를 써서 오해를 막는다.

## 용어 정의

### 데이터 항목 (CSV 제목 줄과 같은 이름)

| 용어                     | 뜻                                                             |
| ------------------------ | -------------------------------------------------------------- |
| 광고비                   | 그날 광고에 쓴 돈 (원)                                         |
| 노출                     | 광고가 화면에 보인 횟수                                        |
| 클릭                     | 광고를 누른 횟수                                               |
| 장바구니                 | 장바구니에 **담은** 횟수                                       |
| 전환                     | **구매 완료** 건수. 화면에서는 "구매" 로 표시                  |
| 매출                     | 광고로 생긴 구매 금액 (원)                                     |
| 매체                     | 광고를 낸 곳: NAVER · META · GOOGLE                            |
| 캠페인 > 광고그룹 > 소재 | 광고 묶음의 큰 단위 > 중간 단위 > 실제 광고 하나 (이미지·영상) |

### 기간

| 용어        | 뜻                                               |
| ----------- | ------------------------------------------------ |
| 기준일      | 데이터에 있는 **가장 마지막 날짜** (오늘이 아님) |
| 최근 7일    | 기준일을 포함한 7일 (기준일 10/7 → 10/1~10/7)    |
| 전주        | 최근 7일 바로 앞의 7일 (9/24~9/30)               |
| 최근 14일   | 기준일을 포함한 14일                             |
| 월 누적     | 기준일이 속한 달과 그 전 2개월, 달마다 합계      |
| 업로드 지연 | 기준일이 어제보다 오래된 상태                    |

### 화면 표현

| 용어        | 뜻                                                                           |
| ----------- | ---------------------------------------------------------------------------- |
| 개선 / 악화 | 지표가 좋은 쪽 / 나쁜 쪽으로 변함 (매출·ROAS 는 ▲ 가 개선, CPA 는 ▼ 가 개선) |
| 변화 (회색) | 좋고 나쁨을 판단하지 않는 지표의 변화 (광고비)                               |
| 퍼널        | 노출 → 클릭 → 장바구니 → 구매 로 고객이 줄어드는 흐름                        |
| 최저        | 매체별 퍼널 비교에서 3개 매체 중 그 단계 비율이 가장 낮은 곳                 |

지표 공식(CTR · CPC · CPB · CPA · ROAS · 담기율 · CVR · 객단가)은 [docs/metrics.md](../../metrics.md) 참고.
